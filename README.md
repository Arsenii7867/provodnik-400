# Проводник 400

Тренажёр нештатных ситуаций для проводников ВСМ-400: сотрудник проходит ветвящиеся сценарии по
карточкам «Ситуаций на борту» и стандартам СТО РЖД, принимает решения под серверным таймером и
видит, как каждое решение двигает две шкалы, лояльность пассажира и рейтинг безопасности.
После прохождения разбор объясняет каждый ход со ссылкой на норму, очки идут в профиль,
достижения, лидерборд бригады и аналитику компетенций; HR и LMS забирают результаты через API.
Сценарии лежат в YAML и меняются без пересборки.

## Как выглядит

![Демонстрация: вход, прохождение под таймером, разбор, профиль, лидерборд, аналитика, карта сценария](docs/media/demo.gif)

Вход с демо-профилями; дашборд с уровнем, уведомлениями, челленджами и сгорающими баллами;
каталог сценариев с фильтрами; прохождение с кольцом таймера, двумя шкалами и цепочкой
ролевой модели; покадровый разбор со стрелками шкал и цитатами норм; профиль с достижениями;
лидерборд по бригаде, депо и компании; аналитика с радаром компетенций и рекомендациями;
карта сценария с графом путей. Экраны по шагам описаны в `docs/user_flow.md`.

Запись выше сделана сквозной проверкой `frontend/e2e/demo.spec.js` на базе из сида: сначала
«Дым в тамбуре» проходится лучшим путём с ответом под таймером, затем таймер оставлен истечь, и
сервер ведёт сценарий по ветке истечения. Та же запись в полном размере и без потери кадров:
[docs/media/demo.webm](docs/media/demo.webm).

## Онлайн-демо

Адрес развёрнутого прототипа появится здесь после установки на сервер; до этого запуск по
инструкции ниже занимает несколько минут.

## Как запустить

Нужны Python 3.13 и Node 22 (или новее). Сервер из папки `backend`.

Windows:

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Linux и macOS:

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Фронт из папки `frontend`, после чего всё приложение доступно на `http://localhost:8000`:

```
npm ci
npm run build
```

Проверка: `http://localhost:8000/api/health` отвечает JSON со статусом `ok`, описание API на
`http://localhost:8000/docs`. Демо-вход: коды `VSM-1001` и `VSM-1002` (проводники), `VSM-2001`
(наставник), PIN `1234` (переменная `DEMO_PIN`). Все сотрудники синтетические. Сид
идемпотентен, при `AUTO_SEED=1` сервер сам заполняет пустую базу. Флаг `--no-proxy-headers`
запрещает uvicorn верить заголовку `X-Forwarded-For`: лимит попыток входа считает адреса
соединений, а не то, что прислал клиент; за доверенным прокси флаг убирают. Настройки читаются
из окружения, список с пояснениями в `.env.example`.

Для разработки фронта `npm run dev` поднимает Vite на `http://localhost:5173` с прокси
запросов `/api` на сервер.

## Проверка

Тесты и линтер живут в отдельном файле зависимостей, из папки `backend`:

```
pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
python -m app.scenarios.validator ../content
```

Из папки `frontend`: `npm test` (логика таймера и графиков), `npx playwright test` (сквозные
проверки в браузере: сами поднимают сервер на порту 8010 с собранным фронтом). Все проверки
разом запускает `scripts/check.sh` из корня репозитория.

## Где что лежит

| Путь | Что там |
|---|---|
| `backend/app` | сервер на FastAPI: настройки, база, вход по коду и PIN, единый формат ошибок |
| `backend/app/api` | маршруты по доменам: авторизация, профиль, сценарии, прохождение, разбор, достижения, лидерборд, уведомления, челленджи, аналитика, интеграция, администрирование |
| `backend/app/scenarios` | движок прохождения, загрузчик, валидатор, перебор путей, граф и хранилище контента с перечитыванием |
| `backend/app/services` | прохождение с серверными таймерами, итог, XP и уровни, достижения, челленджи, уведомления, события для LMS, рейтинг, аналитика |
| `backend/tests` | тесты pytest на временной SQLite, сломанные сценарии в `tests/fixtures/broken` |
| `content` | справочники и сценарии в YAML, формат в `docs/scenarios.md` |
| `frontend/src` | интерфейс на React, данные только через `src/lib/api.js` |
| `frontend/e2e` | сквозные проверки Playwright |
| `docs` | архитектура с диаграммами, API, пользовательские сценарии, формат сценариев, безопасность, план развития, `openapi.json` |
| `scripts/check.sh` | все проверки одной командой |

## Как добавить сценарий

1. Создать `content/scenarios/<id>.yaml` по образцу `content/scenarios/smoking_vestibule.yaml`:
   шапка, контекст, стартовые шкалы, узлы с вариантами, таймер с веткой истечения, разбор с
   ссылками на `content/refs.yaml`.
2. Запустить валидатор из папки `backend`: `python -m app.scenarios.validator ../content`,
   добиться строки `ИТОГ` с `ошибок=0`.
3. Ничего не перезапускать: сервер перечитывает изменённые файлы сам, наставник может нажать
   `POST /api/admin/scenarios/reload`, и все сотрудники получат уведомление о новом сценарии.
   Подробности и репетиции живого изменения в `docs/scenarios.md`.

## Документация

- `docs/architecture.md`: компоненты, последовательность прохождения с таймером, таблицы,
  решения и их причины.
- `docs/api.md`: авторизация, формат ошибок, все маршруты с примерами curl, интеграция с HR и
  LMS; `docs/openapi.json` та же схема, что на `/docs`.
- `docs/user_flow.md`: путь проводника, наставника и HR-системы, два разобранных сценария.
- `docs/scenarios.md`: формат YAML, валидатор, ссылки на нормы, репетиции живого изменения.
- `docs/security.md`: данные, секреты, роли, лимиты, что не сделано.
- `docs/roadmap.md`: ограничения и план развития.

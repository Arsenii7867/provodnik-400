# Изоляция состояния прохождения при навигации

Результаты исходного исправления сохранены ниже. Текущая версия и проверки всех браузеров:
[сводка перед сдачей](verification.md).

## Проблема

React сохранял экземпляр `PlayPage` при переходе между `/play/A` и `/play/B`.
Во время загрузки экран показывал решения, шкалы и `busy` предыдущей попытки.
Поздний ответ старого GET или POST мог подменить состояние. При переходе кнопками
истории адресная строка и экран могли показывать разные прохождения.
Серверные проверки прав и номера шага не устраняли эту путаницу.

## Решение и ревью плана

Внешний `PlayPage` читает параметр маршрута и создаёт `PlayRun` с React-ключом `runId`.
При смене ID данные, ошибка, уведомление и блокировка получают отдельное состояние.
Загрузчик возвращает Promise, не меняя состояние; эффект проверяет отмену перед
применением ответа или ошибки. При уходе выполняется очистка повтора истечения.

План прошёл независимое ревью. Для изоляции используется жизненный цикл React,
без общей таблицы запросов или глобального состояния. API, серверные дедлайны,
начисления и бизнес-правила не меняются. Исходная правка разрабатывалась в отдельной
ветке от `origin/main`, без зависимости от предыдущего PR.

Игнорирование ответа не отменяет принятого сервером действия. При возвращении
клиент читает актуальное состояние. Смена ID сбрасывает локальные данные;
несохранённой формы на этом экране нет.

Изоляция React не защищает общее смещение часов в `api.js`.
Последующая [защита замеров времени](clock-samples.md) отбрасывает старый замер,
если принят более новый. Локальное состояние и оценка часов защищены разными
механизмами; оба сохраняют серверный дедлайн.

## Проверка

Регрессии создают реальные попытки A и B, переходят между ними через историю
браузера и удерживают ответ GET A. Пока A загружается, решения B недоступны.
После возврата к B поздний успешный ответ или ошибка A не должны менять экран.
Тест сверяет и содержимое экрана, и адресную строку.

Результаты 27 сентября 2026, Windows, Node 24.19.0, установленный Chrome:

- До исправления обе регрессии падали: оставались четыре старые кнопки, поздний
  успешный ответ подменял заголовок сценария, поздний 503 оставлял ошибку другого прохождения.
- После исправления: 22 frontend unit-теста прошли; production build успешен.
- Полный Chrome E2E: 27 passed, 1 ожидаемый пропуск мобильного теста; код выхода 0.
- `git diff --check` прошёл. План и итоговый код проверены независимыми субагентами;
  блокирующих замечаний нет.

Backend и контент не изменены; полный pytest в этой итерации не запускался.
Проверены GET success/error; гонка позднего POST тестом не воспроизводилась.
Результат локального Chrome не подтверждает CI или другие браузеры.

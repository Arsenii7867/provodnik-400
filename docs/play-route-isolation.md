# Изоляция состояния прохождения при навигации

## Проблема

React сохранял экземпляр `PlayPage` при переходе между `/play/A` и `/play/B`.
Пока загружалась новая попытка, экран продолжал показывать старые решения, шкалы и `busy`.
Поздний ответ старого GET или POST мог затем заменить состояние текущего экрана.
В частности, после возврата кнопками истории в заголовке адреса могла быть одна попытка,
а на экране другая. Серверные проверки прав и номера шага не устраняют эту путаницу.

## Решение и ревью плана

Внешний `PlayPage` читает параметр маршрута и создаёт `PlayRun` с React-ключом `runId`.
Смена ID создаёт отдельное состояние: данные, ошибка, уведомление и блокировка относятся
только к своей попытке. Загрузчик возвращает Promise без изменения состояния; эффект
проверяет отмену перед применением результата или ошибки. Существующий cleanup повтора
истечения выполняется при уходе из попытки.

План проверен независимым ревью. Выбран штатный жизненный цикл React вместо общей таблицы
запросов или глобального состояния. API, серверные дедлайны, начисления и бизнес-правила
не меняются. Это отдельная ветка от `origin/main`, без зависимости от предыдущего PR.

Отмена применения ответа не отменяет уже принятое сервером действие. При возвращении в
попытку клиент читает актуальное состояние с сервера. При смене ID локальное состояние
намеренно сбрасывается; несохранённой формы на этом экране нет.

Граница исправления: смещение серверных часов в `api.js` пока общее. Запоздалый ответ
может обновить эту оценку ещё до возвращения Promise компоненту. Отбрасывание устаревших
образцов времени требует отдельной правки общего API-клиента и тестов порядка ответов;
текущий PR изолирует локальные данные и сообщения экрана, но не решает гонку образцов часов.

## Проверка

Регрессии создают настоящие попытки A и B, переходят через историю браузера между ними и
удерживают ответ GET A. Пока A загружается, решения B недоступны. После возврата к B
поздний успешный ответ или ошибка A не должны менять экран B. Содержимое экрана проверяется
отдельно от адресной строки, чтобы тест не ограничивался фактом навигации.

Результаты 27 сентября 2026, Windows, Node 24.19.0, установленный Chrome:

- До исправления обе новые регрессии падали: оставались четыре старые кнопки, поздний
  успешный ответ подменял заголовок сценария, поздний 503 оставлял ошибку другого прохождения.
- После исправления: 22 frontend unit-теста прошли; production build успешен.
- Полный Chrome E2E: 27 passed, 1 ожидаемый пропуск мобильного теста; код выхода 0.
- `git diff --check` прошёл. План и итоговый код проверены независимыми субагентами;
  блокирующих замечаний нет.

Backend и контент не изменены; отдельный полный pytest в этой итерации не запускался.
Отдельная гонка позднего POST не воспроизводилась тестом; проверены GET success/error.
CI и другие браузеры не следует считать проверенными по результатам локального Chrome.

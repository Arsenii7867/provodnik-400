# Восстановление загрузки экрана

При сетевом сбое экран раньше показывал ошибку без возможности повторить запрос.
Теперь рядом с ошибками чтения данных есть кнопка «Повторить»: она повторяет
загрузку текущего ресурса, сохраняя маршрут и фильтры. Пока запрос выполняется,
повторная кнопка недоступна; после нового сбоя можно повторить ещё раз.

Общий компонент LoadError использует reload существующего useLoad. Начальная
загрузка прохождения повторяется внутри PlayRun для того же runId. Защита
от ответов после ухода с экрана сохранена. Ошибки выбора ответа и запуска
сценария не подключены к этому механизму, автоматического повтора POST нет.

Правила времени, начислений и завершения прохождения не меняются. Если при
восстановлении загрузки серверный дедлайн уже прошёл, остаётся существующая
обработка истечения, включая запрос expire. Продуктовые вопросы о технических
сбоях и старте таймера записаны в roadmap.md для отдельного решения.

## Проверка

Регрессии в frontend/e2e/load-retry.spec.js проверяют:

- сетевой сбой каталога, повторный ответ 503, блокировку кнопки и успешный
  следующий повтор с сохранением фильтра;
- восстановление общего профиля и имени в шапке;
- восстановление того же прохождения и текущего хода.

Во всех трёх сценариях сохраняется документ браузера и проверяется отсутствие
дополнительных записывающих API-запросов. Проверка прохождения выполняется до
истечения дедлайна. До изменения проверка каталога падала из-за отсутствия кнопки.

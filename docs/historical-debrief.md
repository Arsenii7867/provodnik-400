# Решение: сохранность исторического разбора

## Проблема и границы

Разбор завершённого прохождения раньше подставлял объяснения и нормы из текущего
YAML. Правка контента меняла историю, а удаление сценария закрывало доступ к ней.
Сохраняем учебную обратную связь без изменения правил активного live edit,
дедлайнов, начислений и повторного прохождения.

## Хранение и транзакция

Используется существующий JSON состояния прохождения, без изменения схемы БД.
При фиксации хода сохраняется снимок объяснений, реплики пассажира, лучшего
варианта и развёрнутых ссылок на нормы из контента, которым рассчитан этот ход.
Это важно при правке сценария между двумя ходами.

При завершении после записи результатов и наград сохраняется полный ответ
разбора, включая концовку, уровни, компетенции, достижения и челленджи. Снимок
и начисления фиксируются одной транзакцией; ошибка сохранения откатывает всё.
JSON записывается новым значением, а не только изменением вложенного словаря.
GET проверяет владельца и завершённость, затем читает сохранённый ответ без YAML.

Формат снимков имеет версию. Неизвестная версия не считается достоверным снимком.
Снимок увеличивает размер состояния пропорционально числу ходов и объёму цитат;
он не содержит копии всего каталога. Изменение формата в будущем потребует
совместимого чтения или явного преобразования сохранённых снимков.

## Старые записи

API сообщает history_status: snapshot, partial или legacy. У каждого шага
есть history_status: snapshot либо legacy. Интерфейс показывает предупреждение
для отсутствующих исторических данных.

- snapshot: все шаги и итог сохранены при выполнении.
- partial: итог сохранён, но ранние шаги старого активного прохождения не имели
  снимков. Их пояснения восстановлены по контенту на момент завершения.
- legacy: у завершённой записи нет поддерживаемого снимка. GET ничего не пишет;
  отдаёт сохранённые результаты и доступные пояснения по текущему контенту.
  Если сценарий удалён, вместо 404 возвращаются записанные шаги, а недоступные
  тексты остаются пустыми. Вычисляемые поля старого разбора могут меняться.

Утраченные исторические тексты восстановить достоверно невозможно. Автоматического
backfill с заявлением исторической точности нет. Активные сценарии продолжают
видеть live edit; закрепление всей версии сценария при старте в эту задачу не входит.

План и архитектура прошли независимое ревью до реализации. Фактические результаты
регрессий и проверок фиксируются в описании PR для проверенной ревизии.

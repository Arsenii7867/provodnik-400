# Ограничения и план развития

Выполнены исправления из [ревью от 27 сентября](audit-2026-09-27.md): предел ожидания сети,
чтение неподтверждённых событий LMS и сохранение фактического лимита таймера в разборе.
Последующие изменения изолировали [состояние прохождения](play-route-isolation.md) и
защитили [замеры серверного времени](clock-samples.md). Добавлен
[ручной повтор загрузки](load-retry.md) после сетевого сбоя. Подтверждённые результаты и границы
проверки приведены в [сводке CI](verification.md). Оставшиеся задачи перечислены ниже.

## Что есть сейчас

Работающий тренажёр из одного процесса: восемь ветвящихся сценариев по карточкам «Ситуаций на
борту» и стандартам СТО РЖД с серверными таймерами, две шкалы, разбор с цитатами норм, профиль,
достижения, лидерборд, челленджи со сгорающими баллами, уведомления, аналитика личная и по
бригаде, API для HR и LMS, валидатор сценариев и живое изменение контента без пересборки.

## Ограничения

1. Контент: восемь сценариев из 51 карточки ситуаций; классы «комфорт» и «первый» покрыты по
   одному-двум сценариям, «стандарт» двумя. Сценарии пишутся в YAML руками методиста и
   проверяются валидатором в терминале: редактора сценариев в интерфейсе нет.
2. База: в демо SQLite файлом (`backend/data`), один процесс uvicorn. Совместимость PostgreSQL 17,
   браузеры и ограниченную нагрузку проверяет [отдельный workflow](extended-checks.md).
   Горизонтальное масштабирование и длительная нагрузка в этот набор не входят.
3. Развёртывание: локальный Docker/Compose и запуск одной кнопкой готовы, но сервер для
   онлайн-демо и production-профиль с PostgreSQL, TLS, миграциями и резервным копированием не
   подняты.
4. Лимит попыток входа хранится в памяти процесса: при нескольких воркерах или перезапуске
   счётчики сбрасываются.
5. Люди и история синтетические: имена из словарей, прохождения сгенерированы движком с
   заданным зерном. Контракт интеграционного API проверен тестами и сквозными запросами;
   реальная внешняя HR-система или LMS не подключена.
6. Офлайн-режима нет: прохождение требует соединения с сервером на каждом ходу, потому что
   таймер и исход решает сервер.
7. Аналитика считается на каждое чтение по истории сотрудника без кэша; динамика по неделям
   считается по датам UTC; уведомления отдаются последними ста без пагинации.
8. Текст узла, выбранного ответа и фактический лимит таймера сохраняются на момент хода.
   Пояснения «почему» и «как лучше», реплика пассажира и ссылки на нормы берутся из текущего
   сценария; полного исторического снимка разбора нет. После удаления варианта пояснение
   может сообщить «вариант изменён».
9. Исходящие события для LMS лежат в таблице: архив читается по курсору, непрерывная доставка
   через `pending_only=true` возвращает неподтверждённые события до ACK. Подтверждения общие
   для одного логического потребителя; доставки по webhook и раздельных ACK для HR/LMS нет.
10. У сотрудника одно активное прохождение: старт нового прерывает незаконченное.

## План развития

1. Контент до 51 ситуации: следующие четыре сценария уже спроектированы (конфликт из-за детей
   в комфорт-классе, розетка и планшет в первом классе, животное без переноски и сосед с
   аллергией, задержка в пути и жалоба), дальше остальные карточки по классам обслуживания, с
   покрытием каждой компетенции не меньше чем тремя сценариями.
2. Разметка компетенций методистами: веса компетенций по сценариям, привязка каждой нормы к
   пунктам стандартов с ревизией реконструированной нумерации, редактирование `content/refs.yaml` из
   интерфейса.
3. Редактор сценариев в интерфейсе наставника: форма узла и варианта, встроенный валидатор с
   теми же кодами ошибок, предпросмотр графа и путей, публикация через существующий
   `POST /api/admin/scenarios/reload`.
4. Промышленное развёртывание: поверх готового локального Docker/Compose добавить профиль
   Compose/Helm с PostgreSQL, Alembic-миграции существующих данных, резервное копирование,
   скрипт установки на сервер и HTTPS на прокси. Совместимость с живым PostgreSQL проверяется
   отдельно; несколько экземпляров и production-инфраструктура пока не подтверждены.
5. SSO по корпоративной учётной записи вместо PIN, httpOnly cookie с защитой от CSRF, таблица
   аудита входов, общее хранилище счётчиков лимита для нескольких процессов.
6. Мобильный клиент с офлайн-очередью для сценариев без таймера: ходы копятся на устройстве и
   применяются сервером при появлении сети, сценарии с таймером остаются только онлайн.
7. Антифрод рейтинга: сигналы аномальных прохождений (одинаковые последовательности ходов у
   разных сотрудников, серии повторов одного сценария, ответы за доли секунды), отдельная
   витрина для наставника и исключение помеченных прохождений из лидерборда.
8. Бригадные челленджи: общая цель на бригаду (например, все проводники без инцидента за
   неделю), командный бонус и лидерборд бригад между депо.
9. Доставка событий в LMS по webhook с повторами и подписью, экспорт результатов в формате xAPI.
10. Кэш аналитики по последнему прохождению сотрудника, пагинация уведомлений, недели по часовому
    поясу депо, снимок текстов разбора в момент хода.

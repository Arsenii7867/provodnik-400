## Поле 2. Ссылка на рабочий прототип, запускаемый по README

```text
Прототип для локального запуска: https://github.com/Arsenii7867/provodnik-400
Инструкция: https://github.com/Arsenii7867/provodnik-400/blob/main/README.md, раздел «Как запустить».

Нужны Python 3.13 и Node 24 LTS. Сначала собирается frontend, затем запускается FastAPI с env-файлом; пустая демо-база заполняется автоматически. Приложение после запуска: http://localhost:8000, описание API: http://localhost:8000/docs.

Демо-вход при стандартных настройках: VSM-1001 и VSM-1002 (проводники), VSM-2001 (наставник), PIN 1234. Сотрудники и история прохождений синтетические. Прототип содержит восемь ветвящихся сценариев, серверные таймеры, две шкалы, разбор решений, профиль, достижения, лидерборд, уведомления и аналитику.

Дополнительная демонстрация: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/media/demo.webm; GIF встроен в README. Видео дополняет запускаемый прототип. Публичный онлайн-сервер на момент подготовки этого текста не подтверждён.
```

## Поле 3. Описание архитектуры

```text
https://github.com/Arsenii7867/provodnik-400/blob/main/docs/architecture.md

Frontend: React. Backend: FastAPI с отдельными роутерами, движком сценариев и сервисами прогресса. SQLite хранит сотрудников, прохождения, действия, достижения и события интеграции; сценарии и правила находятся в YAML. Сервер раздаёт API и собранный frontend на одном порту.

Движок выполняет условия, флаги, отложенные последствия и переходы между узлами. Сервер проверяет дедлайн и номер шага; результат обновляет XP, уровень, компетенции, достижения и бонусы. Лидерборд рассчитывается по результатам и действующим бонусам. Контент проверяется валидатором и перечитывается без пересборки.

В документе есть диаграммы компонентов, последовательности прохождения и данных; SVG и Mermaid-источники находятся в docs/img и docs/diagrams. Конфигурация для PostgreSQL предусмотрена, но работа на PostgreSQL и горизонтальное масштабирование не подтверждены испытаниями.
```

```text
API описывает вход, профиль, каталог, прохождение и разбор, достижения, лидерборд, уведомления, челленджи и аналитику. HR/LMS-контракт с X-API-Key предоставляет создание сотрудников, результаты, журнал действий и события с курсором и подтверждением. Swagger доступен локально на /docs после запуска. Реальная внешняя HR/LMS и отдельный адаптер биллинга не подключены.

User Flow охватывает проводника, наставника и интеграционную систему. Примеры показывают условия и несколько исходов, таймер с последствиями истечения, независимые изменения лояльности и безопасности, обратную связь с объяснениями и ссылками на нормы.
```

## Поле 5. Ограничения и план развития

```text
Ограничения и план: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/roadmap.md
Безопасность: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/security.md
Матрица соответствия исходному заданию: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/hackathon-compliance.md

Ограничения: восемь сценариев, SQLite и один процесс, лимит входа в памяти, синтетические данные, отсутствие SSO и офлайн-режима. Токен хранится в localStorage; HTTPS требует обратного прокси. Локальный Docker-запуск подготовлен, публичное и промышленное развёртывание не заявляются. PostgreSQL, несколько экземпляров, миграции, резервное копирование и нагрузочные показатели не проверены. Сценарии редактируются в YAML; исторический разбор использует текущие тексты. Уведомления о сгорании создаются при обращении пользователя, события LMS читаются по курсору без webhook-доставки. Предметная сверка цитат с официальными материалами и корпоративная/юридическая приёмка остаются необходимыми.

План развития: расширение и методическая проверка контента, редактор сценариев, production-профиль с миграциями/TLS, испытания PostgreSQL и нескольких экземпляров, SSO, централизованные лимиты входа, резервное копирование и аудит, снимки текстов разбора, нагрузочные испытания, webhook/xAPI, антифрод и бригадные челленджи.
```

## Подготовка защиты

Кейс оценивает понимание решения командой отдельно от работоспособности продукта. Каждому участнику нужно лично объяснить движок, формулу очков и архитектурные решения, найти код и выполнить живую правку сценария или шкалы. Репетиции и карта файлов в handoff-памятке помогают подготовиться, но не доказывают прохождение этого критерия. Использование ИИ как вспомогательного инструмента разрешено исходным заданием; понимание кода и фактическое авторство нельзя подменять текстом формы или переписыванием Git-истории.

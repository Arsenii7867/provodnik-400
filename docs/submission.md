## Поле 2. Ссылка на рабочий прототип, запускаемый по README

```text
Прототип для локального запуска: https://github.com/Arsenii7867/provodnik-400
Инструкция: https://github.com/Arsenii7867/provodnik-400/blob/main/README.md, раздел «Как запустить».

Для запуска через Docker установите Docker Desktop. На Windows откройте start.cmd, на Linux/macOS выполните ./scripts/start.sh. Скрипт сохраняет существующий .env, собирает контейнер и ждёт готовности базы, контента и интерфейса. Остановка через stop.cmd или ./scripts/stop.sh сохраняет SQLite в именованном томе.

Для ручного запуска по README нужны Python 3.13 и Node 24 LTS. Сначала собирается frontend, затем запускается FastAPI с env-файлом. Пустая демо-база заполняется автоматически. Адрес по умолчанию: http://localhost:8000; описание API: http://localhost:8000/docs.

Демо-вход при стандартных настройках: VSM-1001 и VSM-1002 (проводники), VSM-2001 (наставник), PIN 1234. Сотрудники и история прохождений синтетические. Прототип содержит восемь ветвящихся сценариев, серверные таймеры, две шкалы, разбор решений, профиль, достижения, лидерборд, уведомления и аналитику.

Запись демонстрации: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/media/demo.webm; GIF встроен в README. Публичный сервер не развёрнут; приложение запускается локально по инструкции выше.
```

## Поле 3. Описание архитектуры

```text
https://github.com/Arsenii7867/provodnik-400/blob/main/docs/architecture.md

Frontend: React. Backend: FastAPI с отдельными роутерами, движком сценариев и сервисами прогресса. SQLite хранит сотрудников, прохождения, действия, достижения и события интеграции; сценарии и правила находятся в YAML. Сервер раздаёт API и собранный frontend на одном порту.

Движок выполняет условия, флаги, отложенные последствия и переходы между узлами. Сервер проверяет дедлайн и номер шага; результат обновляет XP, уровень, компетенции, достижения и бонусы. Лидерборд рассчитывается по результатам и действующим бонусам. Контент проверяется валидатором и перечитывается без пересборки.

Диаграммы компонентов, последовательности прохождения и данных доступны в SVG и Mermaid: docs/img и docs/diagrams. PostgreSQL проверен семью API-тестами, браузерными E2E и ограниченной нагрузкой на 10/25 пользователей. Несколько процессов и горизонтальное масштабирование не проверены.
```

```text

Пример «Дым в тамбуре»: https://github.com/Arsenii7867/provodnik-400/blob/main/content/scenarios/smoking_vestibule.yaml
Пример «Давит в груди»: https://github.com/Arsenii7867/provodnik-400/blob/main/content/scenarios/medical_chest_pain.yaml

API описывает вход, профиль, каталог, прохождение и разбор, достижения, лидерборд, уведомления, челленджи и аналитику. HR/LMS-контракт с X-API-Key позволяет создавать сотрудников, получать результаты, журнал действий и архив событий. Непрерывная доставка использует чтение неподтверждённых событий (pending_only=true), идемпотентную обработку и ACK одного логического получателя. Swagger доступен локально на /docs после запуска. Реальная внешняя HR/LMS и отдельный адаптер биллинга не подключены.

User Flow охватывает проводника, наставника и интеграционную систему. Примеры показывают условия и несколько исходов, таймер с последствиями истечения, независимые изменения лояльности и безопасности, обратную связь с объяснениями и ссылками на нормы.
```

## Поле 5. Ограничения и план развития

```text
Ограничения и план: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/roadmap.md
Безопасность: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/security.md
Матрица соответствия исходному заданию: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/hackathon-compliance.md
Результаты проверок: https://github.com/Arsenii7867/provodnik-400/blob/main/docs/verification.md

В прототипе восемь сценариев, SQLite и один процесс, лимит входа в памяти и синтетические данные. SSO и офлайн-режима нет. Токен хранится в localStorage; для HTTPS нужен обратный прокси. Локальный запуск через Docker подготовлен. Публичное и промышленное развёртывание не выполнены. SQLite и PostgreSQL проверены в одном процессе при ограниченной нагрузке на 10/25 пользователей. Несколько экземпляров, длительная нагрузка, миграции, резервное копирование и промышленная производительность не проверены.

Сценарии редактируются в YAML. Новые ходы сохраняют учебные объяснения и нормы; при завершении полный разбор записывается в state_json атомарно. Снимок версии 1 не требует миграции таблиц. Старые записи без снимков отмечены legacy, итоги с ранними шагами без снимков отмечены partial. Утраченные исторические тексты нельзя восстановить достоверно. Удаление YAML сохраняет доступ к записанным результатам и шагам. Формат описан в docs/historical-debrief.md.

Уведомления о сгорании создаются при обращении пользователя. События LMS читаются через pending_only=true до общего ACK; возможны повторные доставки. Курсор служит для архива. Webhook-доставки и независимых ACK нескольких получателей нет.

Объём сверки с официальными материалами описан в матрице соответствия. Результаты технических проверок с привязкой к ревизии приведены в docs/verification.md. Перед реальным обучением нужны методическая, медицинская и корпоративная/юридическая приёмка.

План развития: расширение и методическая проверка контента, редактор сценариев, production-профиль с миграциями/TLS, испытания нескольких экземпляров, SSO, централизованные лимиты входа, резервное копирование и аудит, совместимость будущих форматов снимков разбора, длительные нагрузочные испытания и проверка целевой инфраструктуры, webhook/xAPI, антифрод и бригадные челленджи.
```

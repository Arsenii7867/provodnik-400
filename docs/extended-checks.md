# Проверки браузеров, PostgreSQL и нагрузки

Workflow [«Браузеры, PostgreSQL и нагрузка»](../.github/workflows/extended-check.yml)
запускается вручную из Actions. Каждое задание получает отдельную виртуальную машину.
Запросы идут к приложению через loopback, данные синтетические. Успех прогона
проверяется по результату workflow для конкретного commit SHA.
[Сводка выполненных проверок](verification.md) содержит ссылки на успешные запуски.

## Браузеры

Общий набор E2E запускается в Firefox, WebKit, мобильном Chromium (Pixel 7) и
мобильном WebKit (iPhone 13). Для Chromium с PostgreSQL предусмотрено своё задание. Мобильные
профили эмулируют размеры экрана и касания, физических телефонов в проверке нет.
WebKit проверяет движок, а не конкретную поставку Safari с расширениями и настройками ОС.

E2E охватывают путь каждого из восьми сценариев, перезагрузку, таймеры, XP и разбор,
права на карту, смену аккаунта и восстановление после ошибок сети. Мобильный тест добавляет
семь экранов, отсутствие горизонтального переполнения документа и нажатия кнопок через touch API.
Таблицы с собственной горизонтальной прокруткой допустимы.

Пример локального запуска из `frontend` после подготовки Python-окружения и сборки:

```sh
npm ci
npm run build
npx playwright install firefox
PW_PROJECT=firefox npx playwright test
```

Другие значения `PW_PROJECT`: `chromium`, `webkit`, `mobile-chromium`, `mobile-webkit`.
Без переменной остаётся обычная проверка Chromium/Chrome. CI сохраняет JSON-отчёт,
скриншот и trace при ошибке; артефакты доступны семь дней. Демо-видео в этот набор не входит.

## PostgreSQL

CI поднимает одноразовый PostgreSQL 17. `backend/compat_tests` проверяет создание схемы,
индексы, повторный seed, конкурирующие старты и решения, однократное начисление XP,
достижений и бонуса челленджа, события LMS и запрет чужого прохождения.
Каждый тест создаёт схему с уникальным именем и удаляет только её.
Тест двух разных стартов принудительно пересекает транзакции перед INSERT: без защиты
оба запроса могли оставлять активное прохождение. Старты одного сотрудника теперь
сериализуются блокировкой его строки `FOR NO KEY UPDATE` до проверки Idempotency-Key;
новый старт закрывает предыдущее прохождение. Блокировка совместима с проверками внешних
ключей при параллельном завершении, поэтому эти операции не блокируют друг друга на сотруднике.

Для отдельной тестовой БД из `backend`:

```sh
POSTGRES_TEST_URL='postgresql+psycopg://USER:PASSWORD@127.0.0.1:5432/TEST_DB' \
  .venv/bin/pytest -v compat_tests
```

Без `POSTGRES_TEST_URL` эти проверки пропускаются; это не успешный прогон PostgreSQL.
`E2E_DATABASE_URL` позволяет запустить браузерный набор на PostgreSQL. В workflow
Chromium проходит весь обычный набор через HTTP запущенного приложения.

## Нагрузка

`scripts/load_check.py` обращается только к loopback HTTP с явно указанным портом;
порт пользовательского демо 8000 запрещён. Для нагрузки создайте тестовую базу.
Тест создаёт сотрудников и выполняет по три прохождения на каждого при 10 и 25
одновременных пользователях. После этого каждый пользователь в течение 60 секунд
читает профиль, каталог, уведомления, аналитику и рейтинг бригады.

Подготовка сотрудников и вход выполняются до замера. Нагрузка моделирует вошедших
пользователей; предельная скорость авторизации не измеряется. Проверяются повтор старта с тем же ключом,
завершение до дедлайна, сумма XP, история, число завершений и отсутствие активного
прохождения после окончания. Непредусмотренный HTTP-ответ или нарушение данных означают неуспешный прогон.

Пример для уже запущенного тестового сервера на порту 8014, из корня репозитория:

```sh
backend/.venv/bin/python scripts/load_check.py --users 25 --steady-read-seconds 60 \
  --output load-results/sqlite-25.json
```

Отчёт содержит количество запросов и завершений, ошибки, длительность, запросы в секунду,
медиану, p95, p99 и максимальную задержку. Общий p95 должен быть не больше 3000 мс.
Порог относится к смеси чтений и записей, а не к каждому endpoint. Прогон на машине CI
не подтверждает пропускную способность других серверов или отсутствие утечек памяти
при длительной работе. PIN, токены и персональные данные в JSON не выводятся.
